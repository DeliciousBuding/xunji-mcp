# 基准：按日读取与派生查询层

[English](benchmark.md) | [简体中文](benchmark.zh-CN.md)

已有结果使用确定性的合成历史数据，通过 `npm run bench` 在本地 workerd
（Miniflare + D1）中测得。本次文档更新没有重跑基准，不涉及真实训练数据。

## 结果

|  天数 | 0.1 方式                                      | 0.1 工具调用数 |                 0.1 输出 | 0.2 概览                  | 0.2 调用数 |           0.2 输出 | 0.2 cold / warm |
| ----: | --------------------------------------------- | -------------: | -----------------------: | ------------------------- | ---------: | -----------------: | --------------: |
|   365 | `xunji_list_training_days`，每次 2 个未缓存日 |            183 |  142,607 B / ~43,830 tok | `xunji_training_overview` |          1 | 1,439 B / ~552 tok |   40 ms / 25 ms |
| 1,095 | 同上                                          |            548 | 427,906 B / ~131,449 tok | `xunji_training_overview` |          1 | 1,444 B / ~555 tok |   61 ms / 37 ms |

旧方式按模型需要 183 或 548 次调用；索引概览在回填完成后只需一次工具调用。
对这些数据集，其序列化 JSON 的字节数约为累计旧范围 payload 的 1/99 至 1/296。

三年的按月分组查询返回 37 行、2,565 B（约 985 tok）。
每次概览会查询索引三次，分别获取总计、月度序列和主要动作。

## 方法

- 数据：每周 4 天有一个合成 session，每个 session 含 5 个动作，
  包括热身和正式组、自重及单侧训练，每 37 天放入一个时长异常。
  通过应用的 `replaceDay()` 函数写入本地 D1；
  这不是生产部署或真实上游回填。
- 0.1 数字：基准重建 `xunji_list_training_days` 的双日 payload 形状，
  序列化每个块，并按 `ceil(days / 2)` 次模拟调用累计。
  没有调用旧 MCP 工具或请求上游。假设每天需要一次上游读取。
  原始产物中的旧方式延迟固定采用每次读取 250 ms、每次工具调用 50 ms，
  属于估算，不是真实运行测量。
- 0.2 数字：`trainingOverview` 查询已填充的本地 D1。
  使用 `performance.now()` 测量填充后的第一次调用（“cold”）和第二次调用（“warm”）。
  这些数字不代表 Worker 冷启动或远程 D1 延迟。
- 字节和 token：测量序列化后的基准 JSON 对象，token 由 `gpt-tokenizer` 估算。
  不包含 MCP envelope、额外文本摘要、prompt 和客户端渲染。
- 两次运行的覆盖范围均完整，每个合成日都已扫描。

## 范围与限制

对已填充的数据集和按日读取模型，索引概览能够减少历史摘要的工具调用次数
及序列化输出量。它没有复现所有旧响应、查询方式或客户端对话。

这些结果不能证明生产延迟、多区域 D1 行为、账户级配额安全，
或首次回填的总时长和成本。真实回填仍须每天读取一次上游，
由 Durable Object alarm 循环执行，并发为 3，
遵守上游节奏和 `SCAN_DAILY_LIMIT`（默认每个 UTC 日 100 天）。
解读全历史结果前须检查覆盖状态；本基准从完整的本地覆盖开始。

## 复现

```bash
npm run bench            # 365 days
BENCH_DAYS=1095 npm run bench
```

这些命令运行本地合成基准，不是生产探测。
原始产物：[365 天](../bench/results-365.json)和
[1,095 天](../bench/results-1095.json)。
测量代码见 [bench/bench.test.ts](../bench/bench.test.ts)。
独立的历史核验记录见[验收](acceptance.zh-CN.md)。
