# v0.1.0

[English](#english) | [简体中文](#简体中文)

## English

The initial release connects MCP clients to one operator's Xunji training
account through a self-hosted Cloudflare Worker.

### Changes

- Streamable HTTP `/mcp`, OAuth 2.1, CIMD/DCR, PKCE S256, resource discovery,
  audience checks, refresh rotation and revocation.
- Fail-closed operator authorization through Access JWT verification and an
  email allowlist, or a deployment passphrase.
- Training day/range, movement history, statistics, movement catalog and
  official-plan reads; calendar dates use `Asia/Shanghai`.
- Identity-scoped KV cache, per-day Durable Object pacing and explicit
  `pending`/`deferred` results.
- An opt-in training upsert requiring `WRITE_TOOLS_ENABLED=true`,
  `xunji:write` and `confirmed: true`. No `dry_run` is sent and no delete tool
  is exposed.

### Installation and configuration

This is the first release, with no previous release to migrate. Install from
the tag with `npm ci` and generate Worker types with `npm run cf-typegen`.
Create `OAUTH_KV` and `CACHE_KV`, configure `UPSTREAM_GATE` and its class
migration, and set the canonical origin plus Access or passphrase identity.
Keep the vendor key in a Worker secret and writes disabled unless required.

### Validation scope and known limits

The tagged acceptance record reports local typecheck/workerd tests and earlier
private read, OAuth and ChatGPT connection checks. This release body
reconstructs that record; no checks were rerun.

Range reads are bounded rather than a complete-history query. Body/nutrition
tools are outside this version. Key rotation remains operator pending, and a
read-only check does not verify a real write. Client checks apply only to the
deployment/client used.

## 简体中文

首个版本通过自行托管的 Cloudflare Worker，
让 MCP 客户端访问一名操作者的训记训练账号。

### 变化

- 提供 Streamable HTTP `/mcp`、OAuth 2.1、CIMD/DCR、PKCE S256、
  resource 发现、audience 检查、refresh 轮换和撤销。
- 操作者授权采用 Access JWT 验证和邮箱 allowlist，或部署口令；
  未配置时 fail closed。
- 支持训练日及范围、动作历史、统计、动作目录和官方计划读取；
  日历日期使用 `Asia/Shanghai`。
- 按身份隔离的 KV 缓存、按日 Durable Object 限频，
  以及显式 `pending`、`deferred` 结果。
- 可选训练 upsert 需要 `WRITE_TOOLS_ENABLED=true`、`xunji:write`
  和 `confirmed: true`。不发送 `dry_run`，不提供删除工具。

### 安装和配置

这是首个版本，无旧 Release 需要迁移。基于 tag 使用 `npm ci` 安装，
并通过 `npm run cf-typegen` 生成 Worker 类型。
创建 `OAUTH_KV` 和 `CACHE_KV`，配置 `UPSTREAM_GATE` 及其类 migration，
设置 canonical origin 和 Access 或口令身份验证。
上游 Key 保存在 Worker secret 中，按需开启真实写入。

### 核验范围与已知限制

Tag 中的验收记录记载了本地 typecheck、workerd 测试，
以及既有私有读取、OAuth 和 ChatGPT 连接检查。
本 Release 文案据此整理，没有重新执行检查。

范围读取有界，不能直接作为完整历史查询。身体和饮食工具不属于本版本。
Key 轮换仍待操作者处理；只读检查不能验证真实写入。
客户端检查只适用于当时使用的部署和客户端。
