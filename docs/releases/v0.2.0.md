# v0.2.0 · A view of your history / 看见训练历史

[English](#english) | [简体中文](#简体中文)

## English

A derived D1 index makes multi-year training queries available after backfill,
with compact results and explicit coverage.

### Changes

- `xunji_query_training`, `xunji_training_overview`,
  `xunji_movement_progress` and `xunji_history`.
- Resumable Durable Object backfill, retry/backoff, pause/resume and refresh
  replacement of source edits/removals.
- Columnar `structuredContent` with short text summaries; legacy bounded tools
  remain available.
- Separate-key body, food-record and food-search adapters, with a
  `configured`/`verified` capability matrix.
- D1-only historical scans, a today/yesterday hot cache, and default daily
  budgets of 100 attempted scan dates and 300 cache-put attempts.
- Synthetic one-/three-year benchmark artifacts and the official-plan default
  window of seven days before today through 30 days after.

### Upgrade and configuration

From v0.1.0, add the `DB` D1 binding and apply `0001_init.sql` and
`0002_budgets.sql`. Add `SCAN_COORDINATOR` and its Durable Object class migration.
Keep the existing OAuth/cache/gate resources, configure a history start or
submit a backfill, then inspect coverage before querying all history.

Optional domains need the appropriate `body`/`nutrition` configuration and
`XUNJI_BODY_KEY`, `XUNJI_FOOD_KEY` or `XUNJI_FOOD_SEARCH_KEY` secrets.
Training writes remain real opt-in operations requiring `xunji:write` and
`confirmed: true`, with no `dry_run` or delete tool.

### Validation scope and known limits

Validation covered index/coverage, refresh, quota and metric tests, private
backfill checks, and synthetic benchmarks. The benchmark measures local index
queries and models the earlier tool shape; it does not establish production
performance.

At this tag, a real ChatGPT call through the new query tools was still client
pending. Body/nutrition adapters were not live-verified. Initial backfill needs
one upstream read per calendar day, and D1 retains record-level copies.
[Current verification status](https://github.com/DeliciousBuding/xunji-mcp/blob/main/docs/acceptance.md).

## 简体中文

派生 D1 索引让多年训练查询在回填后可用，
并返回紧凑结果和明确的覆盖状态。

### 变化

- 新增 `xunji_query_training`、`xunji_training_overview`、
  `xunji_movement_progress` 和 `xunji_history`。
- Durable Object 支持可恢复回填、重试和退避、暂停及恢复，
  刷新时替换上游编辑或移除的记录副本。
- 使用列式 `structuredContent` 和简短文本摘要，保留旧的有界工具。
- 新增使用独立 Key 的身体、饮食记录和食品搜索适配器，
  通过能力矩阵区分 `configured` 与 `verified`。
- 历史扫描只写 D1，KV 仅缓存今天和昨天；
  默认每日预算为尝试扫描 100 个日期、缓存写入尝试 300 次。
- 提供一年及三年合成基准产物，官方计划默认窗口为今天前七天至后 30 天。

### 升级和配置

从 v0.1.0 升级时，增加 `DB` D1 binding，执行 `0001_init.sql`
和 `0002_budgets.sql` migration。
增加 `SCAN_COORDINATOR` 及其 Durable Object 类 migration。
保留已有 OAuth、缓存和 gate 资源，配置历史起点或提交回填，
解读全历史查询前检查覆盖状态。

可选数据域需要对应的 `body` 或 `nutrition` 配置，以及
`XUNJI_BODY_KEY`、`XUNJI_FOOD_KEY` 或 `XUNJI_FOOD_SEARCH_KEY` secret。
训练写入仍须显式开启、具备 `xunji:write` 和 `confirmed: true`；
它是真实操作，没有 `dry_run` 或删除工具。

### 核验范围与已知限制

验证覆盖索引、覆盖、刷新、额度和指标测试，私有回填检查与合成基准。
基准测量本地索引查询，并模拟旧工具形式，不代表生产性能。

在此 tag 中，通过新查询工具执行真实 ChatGPT 调用仍待客户端确认。
身体与饮食适配器尚未真实验证。首次回填每个日历日需要一次上游读取；
D1 保存记录级持久副本。
