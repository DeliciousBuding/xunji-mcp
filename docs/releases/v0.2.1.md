# v0.2.1

[English](#english) | [简体中文](#简体中文)

## English

The history index tail now advances daily without a client request.

### Changes

- A `10 16 * * *` cron trigger (00:10 `Asia/Shanghai`) enqueues the gap from
  the latest complete/empty day through yesterday and starts the existing
  scanner. Today is picked up on the next run.
- The example configuration sets `workers_dev: false`.
- Deployment and client docs describe the hardened Access gate, removal of the
  deployed passphrase fallback and re-authentication after connector revocation.

### Upgrade and configuration

From v0.2.0, add the cron trigger to the private Worker configuration and retain
the D1/scanner bindings. Configure `HISTORY_START_DATE` or an existing
`history_start`; without a start, scheduled refresh is a no-op. No new D1 schema
migration is introduced.

Apply `workers_dev: false` to existing deployments as well. Once Access works,
remove the deployed `OWNER_PASSPHRASE` and keep any emergency copy privately.
Training writes remain disabled by default, require `xunji:write` and
`confirmed: true`, and have no `dry_run` or delete operation.

### Validation scope and known limits

The tagged acceptance record reports earlier gap-only/exclude-today/no-start
tests, a private scheduled deployment, Access-route checks and a real ChatGPT
query-tool read. These notes preserve that historical scope; no checks were
rerun.

Daily refresh advances the tail; older source edits/removals still need an
explicit refresh. The existing scan budget and vendor pacing still apply.
Optional domain live verification and operator key rotation remain pending.
Historical client results do not establish compatibility for every deployment.

## 简体中文

历史索引末尾现在可以每日更新，无须客户端发起请求。

### 变化

- 增加 `10 16 * * *` cron 触发器（`Asia/Shanghai` 00:10），
  将最新 complete 或 empty 日之后到昨天的缺口入队，并启动已有扫描器。
  今天由下一次运行处理。
- 示例配置设置 `workers_dev: false`。
- 部署和客户端文档说明 Access 入口加固、移除已部署口令回退，
  以及撤销 connector 后重新授权的方法。

### 升级和配置

从 v0.2.0 升级时，将 cron 触发器加入私有 Worker 配置，
保留 D1 和扫描器 binding。
配置 `HISTORY_START_DATE` 或已有 `history_start`；
没有历史起点时定时刷新不执行工作。本版本没有新增 D1 schema migration。

已有部署也须设置 `workers_dev: false`。Access 正常后，
移除已部署的 `OWNER_PASSPHRASE`，应急副本私下保存。
训练写入仍默认关闭，需要 `xunji:write` 和 `confirmed: true`，
没有 `dry_run` 或删除操作。

### 核验范围与已知限制

Tag 中的验收记录记载了既有缺口限定、排除今天及无起点测试，
私有定时部署、Access 路由检查和真实 ChatGPT 查询工具读取。
本页保留这些历史范围，没有重新执行检查。

每日刷新推进索引末尾；较早日期的上游编辑或移除仍须显式刷新。
已有扫描预算和上游读取节奏继续适用。
可选数据域真实核验和操作者 Key 轮换仍待完成。
历史客户端结果不能证明每个部署都兼容。
